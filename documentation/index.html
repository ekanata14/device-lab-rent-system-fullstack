Entity Relationship Diagram (ERD)

All three database tables with columns, data types, and relationships. Based on prisma/schema.prisma.

ℹ️
Note: UserReservation is not a database table — it is a structured JSON object embedded inside Printer.currentUser and Printer.nextReservation. It is shown here to document the JSON shape. The Printer → UsageLog relationship is a logical foreign key (no DB-level constraint) via printerId. LabSettings is a singleton (id always = 1).
erDiagram Printer { String id PK "PRN-XXXX or COM-XXXX" String name String model String type "printer or computer" String status "available, in-use, buffer, broken" DateTime endTime "nullable — session expiry" DateTime bufferEndTime "nullable — buffer expiry" String brokenReason "nullable" Json currentUser "nullable — embedded UserReservation" Json nextReservation "nullable — embedded UserReservation" DateTime createdAt DateTime updatedAt } UsageLog { String id PK "UUID auto-generated" String printerId "logical FK to Printer.id" String printerName "denormalized device name" String userName String studentId Int usageTime "session duration in minutes" DateTime startTime DateTime endTime String photoUrl "nullable — reservation photo path" String stopReason "nullable" String statusAtEnd "completed, force-stopped, broken" String deviceType "printer or computer" DateTime createdAt } LabSettings { Int id PK "singleton — always 1" Boolean isManuallyClosed String openTime "HH:mm format" String closeTime "HH:mm format" String adminPassword "default: admin123" Int bufferMinutes "default: 5" DateTime updatedAt } UserReservation { String name String phone String studentId Int durationInMinutes String photoUrl "nullable" String sessionPassword "nullable — used to force-stop own session" Boolean notifyWhenReady "nullable" } Printer ||--o{ UsageLog : "has logs (printerId)" Printer |o--o| UserReservation : "currentUser (JSON)" Printer |o--o| UserReservation : "nextReservation (JSON)"

Device Status Lifecycle

State machine for a device from creation through all transitions.

stateDiagram-v2 [*] --> available : Device created available --> in_use : POST /reserve\n(User fills booking form) available --> broken : POST /report-broken\n(User reports malfunction) in_use --> buffer : Timer expires (auto)\nor POST /force-stop\n(User or Admin) in_use --> broken : POST /report-broken\nwhile session active buffer --> available : bufferEndTime passes\nno queue buffer --> in_use : bufferEndTime passes\nnextReservation exists buffer --> in_use : POST /resolve\n(Admin skip buffer\n+ queue exists) buffer --> available : POST /resolve\n(Admin skip buffer\n+ no queue) broken --> available : POST /reset\n(Admin marks fixed) state in_use { [*] --> session_active session_active --> session_active : Countdown timer\nrunning session_active --> [*] : User force-stop\nor timer expires } state buffer { [*] --> cooldown cooldown --> [*] : 5-min timer\nor admin skip }
available → reserve → in-use → stop/expire → buffer → timer/skip → available    |    available → report → broken → admin fix → available
